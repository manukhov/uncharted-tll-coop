## Skill::vtable+96 — REJECTS 422760 clear-path hypothesis

Resolved `Skill::`vftable'` `0x142973060` slot +96 → `sub_140664690`:

```c
char sub_140664690() { return 1; }
```

Same pointer in `ScriptSkill`, `IdleSkill`, `NetSkill` vtables (+96).

`Player_SyncControlHostEntityRootOnNetSkip` `0x140422760` clear condition:

```c
if (player+0x1FF0 && !Skill_vtable+96(skill) && Player_ShouldSkipDirectRootTransformApply)
    entity+0x6E &= 0xFA;  // clear bit0 + bit0x4
```

Because `Skill_vtable+96` **always returns 1**, `!1` is false → **clear branch never taken**
for any standard Skill at +0x1FF0. Else branch always runs: root sync + `entity+0x6E |= 1`.

**Prior "smoking gun" via skill+vtable+96 is REJECTED** for stock Skill hierarchy.

Clear path would require a non-Skill object at +0x1FF0 (no writers found besides Skill selector)
or an unmapped Skill subclass overriding +96 to return 0 (not found in vtable scan).
